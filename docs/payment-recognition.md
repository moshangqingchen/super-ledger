# 手机付款识别范围

通知识别只处理用户已启用来源发出的系统通知。微信、支付宝只接受付款服务标题；不读取聊天记录、短信数据库或交易历史。付款只出现在 App 内页面、没有系统通知时，通知权限不能取得它。通知内容隐藏、被系统合并或手机后台限制，也可能漏记。

金额规则区分实付、原价、优惠、余额、手续费。明确的实付金额优先；没有实付合计时，不把付款金额和手续费相加猜测，不通过原价减优惠推算。多个可能金额、未知来源、外币、退款、转账、充值、提现和还款进入待确认。金额无法确定时保持空值，候选值只供用户核对。

付款方式说明余额钱包时，匹配微信或支付宝钱包；说明银行卡时，匹配银行和卡片尾号，并覆盖来源默认账户。同尾号多卡、找不到卡、缺少卡片尾号均待确认。通知没有付款方式时，只有用户明确设置的默认账户可用于自动入账；建议经常更换付款卡的人不要设置此默认值。识别来源是包名及模板匹配，不是对交易真实性或银行短信发送者的密码学认证。

银行短信仍需在手机设置的「添加其他银行 / 短信应用」中启用实际短信应用，并打开自动记账总开关与系统通知访问；启用银行 App 来源不会同时启用短信应用。已知银行服务号码或精确银行显示名的通知，可识别「交易金额／账号／交易内容」形式的单笔消费提醒，以及「尾号…支出(消费…)金额元」形式的原文。独立账号字段仅接受完整的四位值，不把长卡号或分组卡号的首四位当尾号；银行和尾号能唯一匹配人民币银行卡时才自动入账。多个交易金额、交易内容、交易时间或余额字段进入待确认。通知里只显示「新短信」、未提供金额的富媒体占位内容，以及开启采集前的历史短信，均不能由这项通知识别自动补读。

页面辅助识别默认关闭，需要用户自行打开 App 中的独立开关，并在 Android 系统无障碍设置中授权。它还受自动记账总开关和来源开关限制。仅检查微信、支付宝候选付款结果窗口；通用浏览器容器、启动页、聊天页、账单列表和历史详情不在当前模板范围。先检查节点元数据，发现输入框、密码框或聊天结构便停止，不读取输入文字；不截图、不点击、不滑动、不代为付款。

页面必须同时出现独立的成功标题、带标签的付款金额、商家，以及付款方式、订单号或付款时间等佐证，才生成待确认记录。页面来源一律待确认，不直接改变余额。只保存提取的交易字段，不保存整页文字。重复通知和页面记录优先按同来源订单号去重；没有订单号的相同金额短时间记录会提醒核对，仍需防止漏记和重复。

当前回归样例全部为人工合成，不含用户真实通知或真实页面。本机 Java 测试验证金额、账户匹配和结构规则；未在 vivo X200 Ultra、微信或支付宝真实支付流程中验证。页面类名、控件结构或可访问文字不符合模板时会跳过，因此辅助功能不保证覆盖无通知付款。后续可以根据用户自愿提供的匿名样例调整：删除姓名、完整卡号、手机号、订单号等，仅保留服务标题、金额字段和付款方式结构即可。

运行离线规则与账本测试：`powershell -File android/tools/test-unit.ps1`。测试通过不等于 Android 权限、后台存活或真实付款兼容性已验证。

声明与能力依据 Android 官方 [AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService) 和 [AccessibilityServiceInfo](https://developer.android.com/reference/android/accessibilityservice/AccessibilityServiceInfo)：使用 `BIND_ACCESSIBILITY_SERVICE`、显式包名、窗口状态/内容事件和读取窗口能力；`isAccessibilityTool=false`，不请求截图、手势或按键过滤能力。权限由用户在系统中授予，构建和测试不会自动授权。
