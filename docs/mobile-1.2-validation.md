# Android 1.2 / Windows 1.7 验证范围

本次升级把手机版扩展为完整账本，并升级局域网同步的数据协议。传输仍沿用原有临时二维码与 AES-GCM。旧手机可与新电脑同步原有人民币收支；新手机需电脑 1.7 及以上，遇到旧电脑会明确拒绝同步并保留手机内容。

最终回归：120 项 Node 测试、235 项 Java 离线检查（解析 71、账户匹配 16、付款页 24、财务 32、存储 52、更新 40），以及 13 项生产 Java 与 Node 加密同步场景全部通过。新版协议二维码通过桌面编码器与 ZXing 解码联测。Android 1.2.0 / 10200 APK 编译、原 v2/v3 签名与 16 KiB ZIP 对齐通过。

Windows 1.7.0 离线安装包构建及打包后隔离启动通过：界面加载成功，授权 API 返回 200，未授权返回 403。包内同步服务、更新器和公钥与源码一致；附带 APK 与独立发布 APK 字节一致，包内不含个人账本或签名私钥。两端生产更新校验器通过本次清单签名、实际文件长度/哈希及安卓同版本抑制检查。

[v1.7.0 正式发布](https://github.com/moshangqingchen/super-ledger/releases/tag/v1.7.0)的四个附件服务端大小及 SHA-256 与本地一致，标签对应构建源码 `b6f352d`。公开更新入口字节与正式清单一致；实际 Windows 更新策略对 1.6.0 提示 1.7.0、对 1.7.0 不重复提示。公开 APK 经固定代理完整回下载，再由 Android 生产校验器验证通过；Windows 下载地址 HEAD 返回 200，没有重复完整回下载 103 MB EXE，也没有在本轮运行个人安装的覆盖安装器。原个人账本未改动。

## 已实现与验证方式

- 金额：12 种币种、原币整数单位、人民币折算、账户余额、历史汇率、跨币种转账实到账金额、月度预算与收支统计。Java 核心测试覆盖精度、溢出、未来交易排除和原币余额。
- 订阅：月末、闰年、单次/月度、遗漏账期补记、暂停后恢复、不重复补记已删除的账期，使用与电脑相同的账期标识。手机在打开、刷新或同步时检查并补记到期账期，不承诺关闭应用时准点运行。同步测试覆盖两端重复生成同账期。
- 同步：账户、收支、转账、订阅、预算和心愿的逐项基准比较，持久化确认、断线重试、实体冲突、首次离线合并、500 项/2 MB 分批。实际生产 Java SyncClient/LedgerStore 与 Node 服务通过加密局域网接口联测；只替换 Android 平台类型以便在 JDK 运行。
- 识别：用去隐私的合成文本覆盖微信/支付宝买菜消费、实付与优惠、余额、银行卡尾号、同尾号多卡、失败/验证码/汇总通知、退款和重复判断。合成样本不代表真实支付应用在所有版本的通知格式。
- 付款页辅助：默认关闭；Android 系统授权与应用开关分离。服务仅允许微信/支付宝付款窗口，排除聊天、输入、密码、通用网页容器；只提取结构化付款字段，无支付操作或截图。页面结果统一待确认。
- 更新：沿用 APK 原签名和两端更新公钥，校验真实发布清单签名及安装包哈希，验证同版本不再提示。

## 尚需真机核对

当前没有完成 vivo X200 Ultra 真机验证，也没有运行 Android 模拟器。APK 编译与 JDK 测试不能代替原生界面、相机、辅助功能授权、系统安装器及 vivo 后台策略验证。付款页面类名或可访问结构不同会跳过，不能宣称每笔支付均能自动识别。

安装后建议依次核对：已有账本是否保留；扫码合并及账户余额；一笔微信零钱、一笔微信绑卡、一笔支付宝付款的实际金额和账户；通知/付款页同时出现时只入账一次；关闭页面开关后停止采集；实际后台通知情况。不要为测试额外付款，使用正常发生的交易核对即可。

自动记账只修改本地账本余额。汇率自动刷新仍由电脑端完成，手机支持同步汇率与手动汇率。电脑和手机需要连接同一局域网并保持电脑同步窗口打开；这不是跨互联网实时云同步。
